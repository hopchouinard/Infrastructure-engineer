```markdown
# SubAgent User Guide

A guide to using the specialized SubAgents for infrastructure management.

## What are SubAgents?

SubAgents are specialized assistants that help with complex infrastructure tasks. Unlike regular commands that execute specific actions, SubAgents:

- **Investigate** your network to understand context
- **Analyze** configurations and identify issues
- **Plan** complex changes safely
- **Recommend** solutions with detailed execution plans

SubAgents are **read-only** - they investigate and advise, but you execute any changes.

## Available SubAgents

### 1. Infrastructure Design Advisor

**What it does:** Helps you design network architecture, plan VLAN strategies, and make infrastructure decisions.

**When to use:**
- Adding a new category of devices (cameras, IoT, etc.)
- Planning network segmentation
- Reviewing your architecture
- Best practices questions

**How to invoke:**
```
/design <your design question>

Examples:
/design camera network setup for 4 cameras
/design VLAN strategy for IoT devices
/design review my network architecture
```

Or just ask naturally:
```
"How should I set up a network for my security cameras?"
"What's the best way to segment my smart home devices?"
```

### 2. Network Troubleshooter

**What it does:** Diagnoses connectivity and performance issues through systematic investigation.

**When to use:**
- Device keeps disconnecting
- Can't reach another device
- Slow network performance
- WiFi problems

**How to invoke:**
```
/troubleshoot <problem description>

Examples:
/troubleshoot TV keeps disconnecting from WiFi
/troubleshoot laptop can't access NAS
/troubleshoot slow internet on guest network
```

Or just describe the problem:
```
"Why is my TV disconnecting?"
"My laptop can't reach the server"
```

### 3. Security Deep Audit

**What it does:** Comprehensive security analysis of your network configuration.

**When to use:**
- Periodic security review
- After making changes
- Before going "production"
- Compliance checking

**How to invoke:**
```
/security-audit --deep

Options:
/security-audit --deep --focus firewall
/security-audit --deep --focus clients
/security-audit --deep --background
```

### 4. Change Planner

**What it does:** Plans complex multi-step changes with dependency analysis and rollback strategies.

**When to use:**
- Reorganizing VLANs
- Migrating devices
- Complex restructuring
- Any risky changes

**How to invoke:**
```
/plan <change description>

Examples:
/plan reorganize IoT devices into categories
/plan migrate all cameras to new VLAN
/plan consolidate guest networks
```

## Working with SubAgents

### The Investigation Phase

When you invoke a SubAgent, it will:

1. **Acknowledge** your request
2. **Clarify** if needed (asks at most 1-2 questions)
3. **Investigate** your current network configuration
4. **Share findings** as it goes

During investigation, the agent may say:
```
"Let me check your current network configuration..."
"I found 3 VLANs and 45 clients. Now analyzing firewall rules..."
```

### Understanding the Output

SubAgents produce structured output:

**For Design/Planning:**
- Current state analysis
- Options considered
- Recommendation with rationale
- **Execution Plan** (commands for you to run)

**For Troubleshooting:**
- Evidence gathered
- Diagnosis
- Confidence level
- Recommended fix

**For Security Audit:**
- Findings by severity (Critical → Info)
- Specific issues identified
- Remediation steps

### Executing Recommendations

SubAgents **do not** make changes. They produce **Execution Plans** that you run:

```
## Execution Plan

### Step 1: Create IoT VLAN
/infra-isolate --vlan-name "IoT" --vlan-id 30
Expected: VLAN created

### Step 2: Configure firewall
[command]

Review each step, then run the commands yourself.
```

### Asking Follow-up Questions

You can ask for clarification:
- "Can you explain step 3 in more detail?"
- "What if I want to use a different VLAN ID?"
- "What are the risks of this approach?"

## Tips for Best Results

### Be Specific

```
Good: "I want to add 4 security cameras with an NVR that need to
       access local storage but not the internet"

Less helpful: "Set up cameras"
```

### Provide Context

```
Good: "My TV keeps disconnecting, especially in the evenings
       around 7-9 PM when everyone is streaming"

Less helpful: "WiFi is broken"
```

### Review Execution Plans

Before running commands:
- Understand what each step does
- Note the rollback instructions
- Have the `/infra-undo` command ready

## Common Questions

### Q: Can SubAgents break my network?
A: No. SubAgents are read-only. They investigate and recommend, but you execute any changes. You're always in control.

### Q: How do I know which agent to use?
A: Just describe what you need:
- "How should I..." → Design Advisor
- "Why is... having problems?" → Troubleshooter
- "Check my security" → Security Audit
- "Plan how to..." → Change Planner

### Q: Can agents run in the background?
A: Yes, Security Audit supports `--background`. You'll be notified when complete.

### Q: What if the agent is wrong?
A: Agents can make mistakes. Always review recommendations critically. If something doesn't seem right, ask for clarification or don't execute that step.
```

- 3 VLANs in use (1, 20, 50)
- No existing camera infrastructure
- VLAN 60-69 available for security

### Recommendation
Create dedicated "Cameras" VLAN (ID: 60) with:
- Subnet: 192.168.60.0/24
- Firewall: Cameras → NVR only
- Block: Cameras → Internet, other VLANs

### Execution Plan

**Phase 1: Create VLAN**
/infra-isolate --vlan-name "Cameras" --vlan-id 60

[Full execution plan follows...]
```

## Example 2: Troubleshooting WiFi Issues

### User Request
```
/troubleshoot My Samsung TV keeps disconnecting from WiFi,
especially in the evenings.
```

### Agent Response (Summary)
```
Troubleshooter: I'll investigate your TV's connection issues.

[Queries TV client data, checks AP status]

## Diagnostic Report: Samsung TV WiFi Disconnections

### Investigation
- TV Signal: -72 dBm (Poor)
- Connected to: Basement AP (far from TV)
- Closer AP available: Living Room AP
- Evening timing: Correlates with high WiFi usage

### Diagnosis
Root Cause: Weak signal due to connection to distant AP

The TV connected to the Basement AP (-72 dBm) when the Living
Room AP is much closer. Combined with increased evening traffic,
this causes disconnections.

### Recommendations
1. Force reconnect to Living Room AP
2. Consider wired connection (TV is near ethernet)
3. Adjust AP power levels to improve roaming
```

```

Change Planner: I'll plan a safe migration to categorized IoT VLANs.

[Inventories 23 IoT devices, maps dependencies]

## Execution Plan: IoT Categorization

### Summary
- Create 3 new VLANs (Cameras, Sensors, Smart Home)
- Migrate 23 devices in 4 phases
- Estimated time: 45 minutes
- Risk: Medium (brief connectivity loss per device)

### Phase 1: Create Infrastructure
Create VLANs and firewall rules before any migration.

### Phase 2: Migrate Cameras (6 devices)
Lowest risk - cameras are independent.

### Phase 3: Migrate Sensors (12 devices)
Some may need hub access - migrate after hubs.

### Phase 4: Migrate Smart Home Hubs (5 devices)
Migrate last - other devices may depend on them.

### Rollback Strategy
Each phase can be rolled back independently.
Full rollback time: ~30 minutes.
