## 4. Background: Claude Code SubAgents

### 4.1 Task Tool Overview

Claude Code's `Task` tool allows spawning specialized agents (subprocesses) that:
- Run autonomously with their own context
- Have access to specified tools
- Can run in the background
- Return results to the main conversation

### 4.2 Agent Types

The Task tool supports different `subagent_type` values:
- `Explore` - For codebase exploration
- `Plan` - For implementation planning
- `general-purpose` - For complex multi-step tasks
- Custom types defined via configuration

### 4.3 Agent Configuration

Agents are defined through:
1. **AGENT.md files** - Markdown files with YAML frontmatter defining the agent
2. **Slash commands** - User-facing invocation methods (in `.claude/commands/`)

**Supported Frontmatter Fields:**

| Field | Required | Description |
|-------|----------|-------------|
| `name` | Yes | Agent identifier (lowercase-hyphens) |
| `description` | Yes | When to invoke; supports multi-line with `\|` |
| `tools` | No | Comma-separated allowlist of tools |
| `disallowedTools` | No | Comma-separated denylist of tools |
| `model` | No | `sonnet`, `opus`, `haiku`, or `inherit` |

**Example:**
```yaml
---
name: my-agent
description: |
  Description of when this agent should be invoked.
  Include trigger phrases and use cases.
tools: Read, Grep, Glob, mcp__unifi__unifi_list_clients
model: sonnet
---
```

**Note:** Non-standard configuration (like allowed commands, context files, output format) should be documented in the agent's system prompt content, not in frontmatter.

unifi_delete_*
unifi_update_*

1. NOT execute the changes directly
2. Produce an Execution Plan following the standard template

This permission model is enforced through:
1. `tools` field in AGENT.md frontmatter (allowlist)
2. `disallowedTools` field in AGENT.md frontmatter (optional denylist)
3. Agent instructions explicitly prohibiting config operations in the system prompt body

### 5.4 Query Patterns

**File: `.claude/agents/shared/QUERY-PATTERNS.md`**

```markdown
# Common Query Patterns for SubAgents

Standard investigation patterns used across all SubAgents.

## Network Discovery

### Get Complete Network Overview
```
1. unifi_list_networks() → All VLANs and their configs
2. unifi_list_devices() → All switches, APs, gateways
3. unifi_list_clients(active_only=true) → Connected clients
4. unifi_list_firewall_rules() → All firewall rules
```

### Get Specific Device Context
```
1. unifi_get_client(identifier) → Device details
2. If wired: unifi_get_device(switch_mac) → Switch info
3. If wired: unifi_get_port_status(switch, port) → Port details
4. unifi_get_network(device.network) → Network config
```

## Client Analysis

### Find Unknown/Unnamed Clients
```
1. unifi_list_clients() → All clients
2. Filter: name is null OR name matches MAC pattern
3. Group by network/VLAN
4. Identify vendor from MAC prefix
```

### Trace Client History
```
1. unifi_get_client(identifier) → Current state
2. Check: last_seen, uptime, rx_bytes, tx_bytes
3. Check: is_wired vs wireless connection details
4. Review: previous IPs if available
```

## Security Analysis

### Firewall Rule Audit
```
1. unifi_list_firewall_rules() → All rules
2. Check for: action=accept with source=any AND dest=any
3. Check for: disabled rules
4. Check for: guest network access to RFC1918
5. Verify: inter-VLAN isolation rules exist
```

### VLAN Isolation Check
```
1. unifi_list_networks() → Get all VLANs
2. For each non-default VLAN:
   - Check: isolation firewall rule exists
   - Check: no overly permissive rules
3. Special attention to: Guest, IoT VLANs
```

## Troubleshooting Patterns

### Connectivity Issue Investigation
```
1. unifi_get_client(problem_device) → Current status
2. Check: is device connected? last_seen?
3. If wireless: signal strength, AP, channel
4. If wired: port status, VLAN assignment
5. Check: firewall rules that might block traffic
6. Check: DHCP status in network config
```

### Performance Investigation
```
1. unifi_get_client(device) → Traffic stats
2. unifi_get_device(ap_or_switch) → Device load
3. For wireless: channel utilization, interference
4. For wired: port errors, duplex mismatch
```

## Output Formatting

### Standard Device Summary
```markdown
**Device:** [name or MAC]
- Type: [Wired/Wireless]
- Connection: [Switch:Port or AP:Channel]
- Network: [VLAN name] (ID: [vlan_id])
- IP: [ip_address]
- Status: [Online/Offline] (last seen: [timestamp])
```

### Standard Network Summary
```markdown
**Network:** [name]
- VLAN ID: [id]
- Subnet: [subnet]
- Purpose: [corporate/iot/guest]
- Clients: [count] active
- Isolation: [Yes/No]
```
```
