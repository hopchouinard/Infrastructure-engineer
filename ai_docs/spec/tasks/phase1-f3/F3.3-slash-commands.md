## 4. Background: Slash Commands in Claude Code

### 4.1 Command Format

Slash commands are markdown files in `.claude/commands/` with YAML frontmatter:

```yaml
---
description: Brief description shown in autocomplete
allowed-tools: Tool1, Tool2  # Which tools the command can use
argument-hint: <required> [optional]  # Shown in autocomplete
---

# /command-name

Command instructions and workflow...
```

### 4.2 Argument Handling

Commands can access arguments via:
- `$ARGUMENTS` - Full argument string
- `$1`, `$2`, etc. - Positional arguments
- `--flag value` - Named arguments (parsed manually in instructions)

### 4.3 Commands vs Skills

| Aspect | Slash Commands | Skills |
|--------|----------------|--------|
| Invocation | Manual (`/name args`) | Automatic (context) |
| Arguments | Explicit, parsed | Extracted from conversation |
| Scope | Single workflow | Broad capability |
| Use Case | "Do this specific thing" | "Help with this area" |

## 5. Implementation Requirements

### 5.1 Isolate Device Command

**File: `.claude/commands/infra-isolate.md`**

```markdown
---
description: Isolate a device to its own VLAN with optional access rules
allowed-tools: mcp__unifi__*
argument-hint: <device> [--vlan-name <name>] [--vlan-id <id>] [--allow <targets>]
---

# /infra-isolate

Isolate a network device to a dedicated VLAN with optional access to specific destinations.

## Arguments

**Required:**
- `device`: Device identifier (name, MAC address, or IP)

**Optional:**
- `--vlan-name <name>`: Name for the new VLAN (default: "{Device}-Isolated")
- `--vlan-id <id>`: Specific VLAN ID to use (default: auto-assign next available)
- `--allow <targets>`: Comma-separated list of devices/IPs the isolated device can reach

## Parsing Arguments

The full argument string is: `$ARGUMENTS`

Parse as follows:
1. First non-flag argument is the device identifier
2. `--vlan-name` followed by its value
3. `--vlan-id` followed by its value
4. `--allow` followed by comma-separated targets

Example: `/infra-isolate "Samsung TV" --vlan-name "Media-IoT" --allow "NAS,Plex"`
- device = "Samsung TV"
- vlan_name = "Media-IoT"
- allow = ["NAS", "Plex"]

## Workflow

### Step 1: Find the Device

Use `unifi_get_client` with the device identifier.

If device not found:
- List similar devices with `unifi_search_clients`
- Ask user to clarify

Report:
```
Found device: [name]
MAC: [mac], IP: [ip]
Connection: [Wired on Switch:Port] or [Wireless on AP]
Current network: [network_name]
```

### Step 2: Survey Existing Networks

Use `unifi_list_networks` to get all current VLANs.

Determine VLAN ID:
- If `--vlan-id` specified: verify it's not already in use
- Otherwise: find next available ID (suggest 10-99 range for IoT)

Calculate subnet: `192.168.{vlan_id}.0/24`

### Step 3: Find Allow Targets (if specified)

For each target in `--allow`:
- Use `unifi_get_client` to find the device
- Get its IP address for firewall rules

If any target not found, report and ask whether to proceed.

### Step 4: Present Change Plan

```markdown
## Device Isolation Plan

**Device:** [device_name] ([mac])
**Current Network:** [current_network]
**Target VLAN:** [vlan_name] (ID: [vlan_id])
**Subnet:** [subnet]

### Planned Changes:

1. **Create Network/VLAN**
   - Name: [vlan_name]
   - VLAN ID: [vlan_id]
   - Subnet: [subnet]
   - DHCP: Enabled (.10 - .250)
   - Risk: MEDIUM

2. **Configure Switch Port** (if wired)
   - Switch: [switch_name]
   - Port: [port_num]
   - Change: Native VLAN [current] → [new]
   - Risk: MEDIUM
   - Note: Device will briefly lose connectivity

3. **Create Allow Rules** (if targets specified)
   [For each target:]
   - Allow [vlan_name] → [target_name] ([target_ip])
   - Risk: HIGH

4. **Create Isolation Rule**
   - Block [vlan_name] → All RFC1918 addresses
   - Risk: HIGH
   - Note: Placed after allow rules

### After Completion:
- Device will have new IP in [subnet]
- Can only access: [targets or "Internet only"]
- All changes can be undone with `/infra-undo`

**Proceed with this isolation?** [Yes/No]
```

### Step 5: Execute Changes (After "yes")

Execute in this order, tracking rollback IDs:

1. **Create Network**
   ```
   unifi_create_network(
     name=[vlan_name],
     vlan_id=[vlan_id],
     subnet=[subnet],
     purpose="corporate",  # or "iot" if available
     dhcp_enabled=true,
     dhcp_start=[subnet].10,
     dhcp_stop=[subnet].250
   )
   → Save rollback_id_1
   ```

2. **Configure Port** (if wired)
   ```
   unifi_set_port_vlan(
     switch=[switch_mac or name],
     port=[port_num],
     vlan_id=[vlan_id]
   )
   → Save rollback_id_2
   ```

3. **Create Allow Rules** (for each target)
   ```
   unifi_create_firewall_rule(
     name="Allow-[vlan_name]-to-[target_name]",
     ruleset="LAN_IN",
     action="accept",
     source_network=[vlan_name],
     destination_ip=[target_ip],
     protocol="all"
   )
   → Save rollback_id_3, 4, ...
   ```

4. **Create Isolation Rule**
   ```
   unifi_create_firewall_rule(
     name="Block-[vlan_name]-InterVLAN",
     ruleset="LAN_IN",
     action="drop",
     source_network=[vlan_name],
     destination_network="RFC1918"
   )
   → Save rollback_id_n
   ```

### Step 6: Report Results

```markdown
## Isolation Complete ✓

**Device:** [device_name]
**New Network:** [vlan_name] (VLAN [vlan_id])
**New Subnet:** [subnet]

### Changes Made:
✓ Created VLAN [vlan_name]
✓ Configured port [switch]:[port] (if wired)
✓ Created [n] allow rules (if targets)
✓ Created isolation rule

### Rollback Information:
All changes can be undone with `/infra-undo`

Rollback IDs (valid for 60 minutes):
- Network: [rollback_id_1]
- Port: [rollback_id_2]
- Rules: [rollback_id_3, ...]

### Device Status:
The device should reconnect within 30 seconds with a new IP.
Use `/infra-find [device]` to verify the new connection.
```

### Error Handling

If any step fails:
1. Stop execution immediately
2. Report what succeeded and what failed
3. Offer to rollback completed steps

```markdown
## Isolation Failed ✗

**Error at step:** [step_name]
**Reason:** [error_message]

### Completed Before Failure:
- ✓ [step 1]
- ✓ [step 2]
- ✗ [failed step]

### Recovery Options:
1. `/infra-undo` - Rollback completed changes
2. Fix the issue and retry
3. Complete manually in UniFi UI

**Would you like to rollback the completed changes?** [Yes/No]
```
```

---

# /infra-find

Find the physical connection point of a network device.

## Arguments

**Required:**
- `device`: Device identifier (name, MAC address, or IP)

The device argument is: `$ARGUMENTS` (or `$1` if using positional)

## Workflow

### Step 1: Find the Device

Use `unifi_get_client` with the provided identifier.

If not found:
- Try `unifi_search_clients` with the pattern
- List similar devices
- Ask user to select

### Step 2: Determine Connection Type

Check the device data:

**If `is_wired` is true (or `switch_mac` exists):**
→ Device is connected via Ethernet

**If `ap_mac` exists (and not wired):**
→ Device is connected via WiFi

**If neither:**
→ Device may be offline or data is incomplete

### Step 3: Get Connection Details

**For Wired Devices:**
1. Use `unifi_get_device` to get switch details (by switch_mac)
2. Use `unifi_get_port_status` to get port details
3. Gather: switch name, port number, speed, VLAN, PoE status

**For Wireless Devices:**
1. Use `unifi_get_device` to get AP details (by ap_mac)
2. From client data: signal strength, channel, band
3. Gather: AP name, location (if set), signal quality

### Step 4: Report

**For Wired Device:**
```markdown
## Device Location: [Device Name]

**Connection Type:** 🔌 Wired (Ethernet)

### Physical Connection:
| Property | Value |
|----------|-------|
| Switch | [switch_name] |
| Port | [port_number] |
| Speed | [1Gbps / 100Mbps / 10Mbps] |
| Duplex | [Full / Half] |
| PoE | [Enabled / Disabled / N/A] |

### Network Assignment:
| Property | Value |
|----------|-------|
| VLAN | [vlan_name] (ID: [vlan_id]) |
| IP Address | [ip] |
| MAC Address | [mac] |

### Traffic Statistics:
| Direction | Amount |
|-----------|--------|
| Downloaded | [rx_bytes] |
| Uploaded | [tx_bytes] |

### Status:
| Property | Value |
|----------|-------|
| Connected Since | [uptime] |
| Last Activity | [last_seen] |

**Tip:** To change this device's VLAN, use:
`/infra-isolate "[device_name]" --vlan-name "NewNetwork"`
```

**For Wireless Device:**
```markdown
## Device Location: [Device Name]

**Connection Type:** 📶 Wireless (WiFi)

### Wireless Connection:
| Property | Value |
|----------|-------|
| Access Point | [ap_name] |
| Band | [2.4 GHz / 5 GHz / 6 GHz] |
| Channel | [channel] |
| Signal | [signal] dBm ([quality: Excellent/Good/Fair/Poor]) |
| TX Rate | [tx_rate] Mbps |

### Network Assignment:
| Property | Value |
|----------|-------|
| SSID | [ssid_name] |
| VLAN | [vlan_name] (ID: [vlan_id]) |

---
description: Undo recent infrastructure changes
allowed-tools: mcp__unifi__*, Read
argument-hint: [--id <rollback-id>] [--list]
---

# /infra-undo

Undo infrastructure changes using stored rollback data.

## Arguments

**Optional:**
- `--id <rollback-id>`: Specific rollback ID to undo
- `--list`: Show recent changes that can be undone

## Workflow

### If `--list` specified:

Read the change log from `.claude/logs/unifi-changes.log`

```markdown
## Recent Infrastructure Changes

Changes can be undone within 60 minutes of creation.

| Time | Operation | Details | Rollback ID |
|------|-----------|---------|-------------|
| [time] | [tool_name] | [brief params] | [id] |
| ... | ... | ... | ... |

To undo a specific change:
`/infra-undo --id [rollback_id]`

To undo the most recent change:
`/infra-undo`
```

### If `--id` specified:

Use the provided rollback ID directly.

### If no arguments:

Find the most recent rollback ID from the log.

### Execute Undo

The rollback system is handled by the MCP server. Call the appropriate tool with the rollback ID.

**Note:** The exact undo mechanism depends on F2's implementation. The tool may be:
- `unifi_undo(rollback_id=...)`
- Or calling the reverse operation with stored parameters

```markdown
## Undo Confirmation

**Rollback ID:** [id]
**Original Operation:** [tool_name]
**Time:** [timestamp]
**Details:** [params]

**This will reverse the following change:**
[Description of what was done]

**Proceed with undo?** [Yes/No]
```

### Report

```markdown
## Undo Complete ✓

Successfully reversed: [operation description]

**Original Change:**
- Time: [timestamp]
- Operation: [tool_name]

**Current State:**
[Brief description of current state after undo]
```

### Errors

If rollback ID not found or expired:
```markdown
## Undo Failed

**Reason:** Rollback ID not found or expired

### Alternatives:
1. Check available rollbacks: `/infra-undo --list`

### 5.6 Security Audit Command

**File: `.claude/commands/security-audit.md`**

```markdown
---
description: Security audit - quick check or comprehensive SubAgent analysis with --deep
allowed-tools: mcp__unifi__*, Task
argument-hint: [--deep] [--focus <area>] [--background]
---

# /security-audit

Perform security auditing of the UniFi network configuration. Supports two modes:
- **Quick mode** (default): Fast surface-level security checks
- **Deep mode** (`--deep`): Comprehensive analysis via Security Audit SubAgent

## Arguments

**Optional:**
- `--deep`: Launch the Security Audit SubAgent for comprehensive analysis
- `--focus <area>`: Focus on specific area (firewall, clients, networks, devices, all)
- `--background`: Run deep analysis in background (only with --deep)
- `--severity <level>`: Minimum severity to report (critical, warning, all) - quick mode only

## Examples

```
/security-audit                          # Quick audit, all areas
/security-audit --focus firewall         # Quick audit, firewall only
/security-audit --deep                   # Comprehensive SubAgent analysis
/security-audit --deep --focus clients   # Deep analysis focused on clients
/security-audit --deep --background      # Deep analysis in background
```

## Quick Mode (Default)

Without `--deep`, performs rapid security checks in seconds.

### Workflow

#### Step 1: Gather Data

```
networks = unifi_list_networks()
clients = unifi_list_clients()
devices = unifi_list_devices()
rules = unifi_list_firewall_rules()
```

#### Step 2: Check for Common Issues

**Firewall Checks:**
- 🔴 CRITICAL: "Accept any-to-any" rules
- 🔴 CRITICAL: Guest network accessing RFC1918
- 🟡 WARNING: Overly permissive rules (accept without specific port)
- 🟡 WARNING: Disabled rules that might be needed

**Client Checks:**
- 🔴 CRITICAL: Unknown devices on management VLAN
- 🟡 WARNING: Unnamed devices (MAC-only names)
- 🟡 WARNING: IoT devices on main LAN

**Network Checks:**
- 🔴 CRITICAL: VLANs without isolation rules
- 🟡 WARNING: Small DHCP ranges (<50 addresses)

**Device Checks:**
- 🔴 CRITICAL: Network devices offline
- 🟡 WARNING: Devices with pending updates

#### Step 3: Generate Quick Report

```markdown
## Quick Security Audit

*Completed: [timestamp]*

### Summary

| Severity | Count |
|----------|-------|
| 🔴 Critical | [n] |
| 🟡 Warning | [n] |
| 🔵 Info | [n] |

**Rating:** [Good/Fair/Poor/Critical]

---

### Issues Found

[For each issue:]
**[🔴/🟡/🔵] [Issue Title]**
- Location: [where]
- Risk: [brief description]
- Fix: [quick recommendation]

---

### Quick Fixes

[Commands to address critical issues]

---

**For deeper analysis:** `/security-audit --deep`
```

## Deep Mode (--deep)

With `--deep`, launches the Security Audit SubAgent (F4.5) for comprehensive analysis.

> **Dependency:** Deep mode requires F4 (SubAgent Integration) to be implemented. If F4 is not available, the command will gracefully fall back to quick mode with a notification.

### F4 Availability Check

Before attempting to launch the SubAgent, check if F4 is available:

1. If `security-audit` SubAgent is not registered/available:
   - Display: "Deep audit requires SubAgent integration (F4). Running quick audit instead..."
   - Fall back to quick mode automatically
   - Complete quick audit successfully

2. If F4 is available, proceed with deep mode

### Behavior

When `--deep` is specified and F4 is available:

1. **Parse Additional Arguments**
   - `--focus <area>`: Pass to SubAgent as focus constraint
   - `--background`: Run SubAgent in background mode

2. **Launch SubAgent**

```
Task(
  subagent_type="security-audit",
  prompt="Perform comprehensive security audit of the UniFi network.
          Focus: [area or 'all'].
          Analyze firewall rules, client security, network isolation,
          and device configuration. Provide detailed findings with
          severity ratings and remediation plans.",
  description="Security deep audit",
  run_in_background=[true if --background]
)
```

3. **Report Results**

If foreground: SubAgent results displayed directly
If background: "Security audit running in background. You'll be notified when complete."

### Deep Mode Output

The SubAgent produces comprehensive analysis including:
- Executive summary with overall security rating
- Detailed findings organized by category and severity
- CIS/NIST framework references where applicable
- Prioritized remediation plan with execution steps
- Risk assessment for each finding

See F4.5 (Security Audit SubAgent) for full output format.

## Comparison

| Aspect | Quick Mode | Deep Mode (--deep) |
|--------|------------|-------------------|
| Speed | Seconds | Minutes |
| Depth | Surface checks | Comprehensive analysis |
| Background | No | Optional |
| Framework references | No | CIS/NIST |
| Remediation plan | Basic commands | Detailed execution plan |
| Use case | Regular checks | Periodic review, compliance |

## Error Handling

**If MCP tools fail:**
```markdown
## Security Audit Error

Unable to gather network data: [error]

### Suggestions:
1. Verify UniFi controller is accessible
2. Check MCP server status
3. Retry with `/security-audit`
```

**If SubAgent fails to launch (deep mode):**
```markdown
## Deep Audit Failed

Unable to launch Security Audit SubAgent: [error]

### Fallback:
Running quick audit instead...
[Quick audit output]

For deep analysis, ensure F4 SubAgent is configured.
```
```

## 9. Implementation Notes

### 9.1 Argument Parsing

Claude Code doesn't have built-in argument parsing. The command instructions teach Claude how to parse `$ARGUMENTS`:
- Split on whitespace (respecting quotes)
- Identify flags (`--name value`)
- Handle positional vs named arguments

### 9.2 MCP Tool Names

When referencing MCP tools in `allowed-tools`, use the full path format:
`mcp__unifi__unifi_list_networks` or wildcard `mcp__unifi__*`

### 9.3 Rollback Integration

Rollback depends on F2's implementation. Commands assume:
- Configuration tools return `rollback_id` in response
- Rollback IDs are valid for ~60 minutes
- An undo mechanism exists (exact API TBD)
