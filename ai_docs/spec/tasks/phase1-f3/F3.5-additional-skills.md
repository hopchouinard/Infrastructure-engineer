### 4.1 Guest Network Skill

**File: `.claude/skills/guest-network/SKILL.md`**

```markdown
---
name: guest-network-management
description: |
  Creates and manages guest WiFi networks with proper isolation.
  Activates when user asks about guest network, guest WiFi, visitor access,
  or temporary network access.
allowed-tools: mcp__unifi__*, Read, Grep
---

# Guest Network Management Skill

You help users create and manage guest WiFi networks with proper isolation and security.

## Guest Network Best Practices

1. **Isolation**: Guest networks should be isolated from main LAN
2. **Bandwidth Limits**: Consider limiting bandwidth for guests
3. **Captive Portal**: Optional for authentication/terms acceptance
4. **Time Limits**: Consider session timeouts for temporary access

## Available Tools

Use these MCP tools for guest network management:

| Tool | Purpose |
|------|---------|
| `unifi_list_networks` | Check existing networks/VLANs |
| `unifi_create_network` | Create the guest VLAN |
| `unifi_create_firewall_rule` | Create isolation rules |

## Creating a Guest Network

### Step 1: Assess Current Setup

1. List existing networks with `unifi_list_networks`
2. Check if a guest network already exists
3. Identify available VLAN IDs (recommend 50-59 range for guests)

### Step 2: Plan Guest Network

Gather requirements:
- Network name (default: "Guest")
- VLAN ID (default: next available in 50-59)
- Subnet (default: 192.168.{vlan_id}.0/24)
- Password protection? (recommend: yes)
- Bandwidth limits? (optional)
- Captive portal? (optional)

### Step 3: Present Plan

```markdown
## Guest Network Plan

**Network Name:** [name]
**VLAN ID:** [id]
**Subnet:** [subnet]

### Security Features:
- ✓ Isolated from main network
- ✓ Cannot access other VLANs
- [✓/✗] Password protected
- [✓/✗] Bandwidth limited
- [✓/✗] Captive portal

### Firewall Rules:
1. Allow Guest → Internet
2. Block Guest → All RFC1918 (prevents LAN access)
3. Block Guest → Controller (optional, for security)

**Proceed?** [Yes/No]
```

### Step 4: Execute

1. Create VLAN with `unifi_create_network`
   - Set purpose="guest" if supported
   - Enable DHCP

2. Create allow internet rule:
   ```
   unifi_create_firewall_rule(
     name="Allow-Guest-Internet",
     ruleset="GUEST_OUT",
     action="accept",
     destination_type="any"
   )
   ```

3. Create isolation rule:
   ```
   unifi_create_firewall_rule(
     name="Block-Guest-to-LAN",
     ruleset="GUEST_IN",
     action="drop",
     source_network="[guest_vlan]",
     destination_network="RFC1918"
   )
   ```

### Step 5: Report

```markdown
## Guest Network Created ✓

**SSID:** [network_name]
**VLAN:** [vlan_id]
**Subnet:** [subnet]

### How to Connect:
1. Look for "[network_name]" in WiFi networks
2. Enter password: [if set, otherwise "Open network"]

### Security:
- Isolated from main network ✓
- Internet access only ✓

### To Remove:
`/infra-undo` within 60 minutes, or manually delete in UniFi UI
```

## Modifying Guest Networks

For existing guest networks:
- Password changes require UniFi UI (wireless settings)
- VLAN changes follow standard network update flow
- Adding/removing isolation rules uses firewall tools
```

### 4.2 Security Audit Skill

**File: `.claude/skills/security-audit/SKILL.md`**

```markdown
---
name: security-audit
description: |
  Analyzes UniFi network configuration for security issues.
  Activates when user asks about security audit, network security,
  firewall review, suspicious devices, or security best practices.
allowed-tools: mcp__unifi__*, Read, Grep
---

# Security Audit Skill

You perform security audits on UniFi network configurations, identifying potential issues and recommending improvements.

## Audit Categories

### 1. Firewall Analysis

Check for:
- Overly permissive rules (allow any-to-any)
- Disabled rules that should be enabled
- Rules with no logging enabled
- Redundant or conflicting rules
- Missing isolation rules between VLANs

### 2. Client Analysis

Check for:
- Unknown/unnamed devices
- Devices on wrong VLANs (e.g., IoT on main LAN)
- Blocked devices (review if still needed)
- Devices with no recent activity (stale entries)
- Devices using insecure protocols

### 3. Network Analysis

Check for:
- VLANs without proper isolation
- Overlapping subnets
- DHCP exhaustion risk
- Guest network isolation

### 4. Device Analysis

Check for:
- Offline network devices
- Devices with outdated firmware (if detectable)
- Unmanaged devices on management network

## Audit Workflow

### Step 1: Gather Data

```
networks = unifi_list_networks()
clients = unifi_list_clients()
devices = unifi_list_devices()
rules = unifi_list_firewall_rules()
```

### Step 2: Analyze Each Category

For each category, generate findings:

```python
findings = {
    "critical": [],  # Immediate action required
    "warning": [],   # Should be addressed
    "info": []       # Recommendations
}
```

### Step 3: Generate Report

```markdown
## Security Audit Report

*Generated: [timestamp]*

---

### 🔴 Critical Issues ([count])

[For each critical issue:]
**Issue:** [description]
**Risk:** [what could happen]
**Fix:** [how to resolve]

---

### 🟡 Warnings ([count])

[For each warning:]
**Issue:** [description]
**Recommendation:** [what to do]

---

### 🔵 Informational ([count])

[For each info item:]
**Note:** [observation]
**Suggestion:** [optional improvement]

---

### Summary

| Category | Critical | Warning | Info |
|----------|----------|---------|------|
| Firewall | [n] | [n] | [n] |
| Clients | [n] | [n] | [n] |
| Networks | [n] | [n] | [n] |
| Devices | [n] | [n] | [n] |

### Quick Fixes

[List commands to fix critical/warning issues]
```

## Common Findings

### Critical
- "Allow any to any" firewall rule
- Guest network can access LAN
- Management interface exposed to guest VLAN
- Unknown device on management VLAN

### Warning
- IoT device on main LAN (should be isolated)
- Unnamed devices (hard to identify)
- Firewall rules with logging disabled
- VLAN without inter-VLAN blocking

### Info
- Could consolidate similar firewall rules
- Device naming conventions not followed
- Some clients haven't been seen in 30+ days

## Skill vs Command Relationship

### 4.3 Guest Network Command

**File: `.claude/commands/infra-guest.md`**

```markdown
---
description: Create a guest WiFi network with proper isolation
allowed-tools: mcp__unifi__*
argument-hint: [--name <name>] [--vlan-id <id>] [--password <pwd>]
---

# /infra-guest

Create a properly isolated guest WiFi network.

## Arguments

**Optional:**
- `--name <name>`: Network name (default: "Guest")
- `--vlan-id <id>`: VLAN ID (default: auto-assign from 50-59)
- `--password <pwd>`: WiFi password (default: generate random)

## Workflow

### Step 1: Check Existing

Use `unifi_list_networks` to:
- Verify no guest network exists (or offer to reconfigure)
- Find available VLAN ID in guest range (50-59)

### Step 2: Determine Settings

- Name: `$1` or "--name" value or "Guest"
- VLAN ID: "--vlan-id" value or next available in 50-59
- Subnet: 192.168.{vlan_id}.0/24
- Password: "--password" value or generate 12-char random

### Step 3: Present Plan

```markdown
## Guest Network Plan

**SSID:** [name]
**VLAN ID:** [id]
**Subnet:** [subnet]
**Password:** [password or "Will generate"]

### Configuration:
- DHCP: Enabled (.10 - .250)
- Purpose: Guest (isolated)

### Firewall Rules:
1. Allow Guest → Internet (all ports)
2. Block Guest → All LAN traffic (RFC1918)

**Create this guest network?** [Yes/No]
```

### Step 4: Execute

1. Create network:
   ```
   unifi_create_network(
     name=[name],
     vlan_id=[id],
     subnet=[subnet],
     purpose="guest",
     dhcp_enabled=true
   )
   ```

2. Create firewall rules (as described in skill)

### Step 5: Report

```markdown
## Guest Network Created ✓

**SSID:** [name]
**Password:** [password]

### Guest Access:
1. Connect to "[name]" WiFi
2. Enter password above

**Note:** Guest network is isolated from your main network.
Guests can only access the internet.
```
```

### 4.4 Unknown Clients Command

**File: `.claude/commands/infra-unknown.md`**

```markdown
---
description: List unknown or unnamed clients on the network
allowed-tools: mcp__unifi__unifi_list_clients, mcp__unifi__unifi_get_client
argument-hint: [--vlan <name>] [--active-only]
---

# /infra-unknown

Find and list clients that have not been named or identified.

## Arguments

**Optional:**
- `--vlan <name>`: Filter by specific VLAN/network
- `--active-only`: Only show currently connected clients

## Workflow

### Step 1: Get All Clients

```
clients = unifi_list_clients(active_only=[flag])
```

### Step 2: Filter Unknown

A client is "unknown" if:
- Name is empty or null
- Name matches MAC address pattern
- Name is default (hostname from device)

### Step 3: Categorize

Group by:
- Network/VLAN
- Connection type (wired/wireless)
- Last seen time

### Step 4: Present Results

```markdown
## Unknown/Unnamed Clients

*Found [n] unknown clients*

---

### By Network:

#### [Network Name] ([n] unknown)

| MAC | IP | Type | Last Seen | Suggested Name |
|-----|-----|------|-----------|----------------|
| [mac] | [ip] | [W/Eth] | [time] | [suggestion based on vendor] |
| ... | ... | ... | ... | ... |

---

### Vendor Analysis

| Vendor | Count | Typical Device |
|--------|-------|----------------|
| Samsung | 3 | TV, Phone |
| Apple | 2 | iPhone, iPad |
| Unknown | 5 | - |

---

### Actions:

To rename a device:
```
/infra-rename [mac] "Friendly Name"
```

To investigate a device:
```
/infra-find [mac]
```

To block a suspicious device:
```
/infra-block [mac]
```
```
```

### 4.5 Rename Client Command

**File: `.claude/commands/infra-rename.md`**

```markdown
---
description: Rename a client device for easier identification
allowed-tools: mcp__unifi__unifi_get_client, mcp__unifi__unifi_rename_client
argument-hint: <device> <new-name>
---

# /infra-rename

Set a friendly name for a network client.

## Arguments

**Required:**
- `device`: Current device identifier (MAC, IP, or current name)
- `new-name`: New friendly name to assign

## Workflow

### Step 1: Find Device

```
client = unifi_get_client(identifier=[device])
```

If not found, search and suggest matches.

### Step 2: Confirm

```markdown
## Rename Device

**Current:** [current_name or MAC]
**New Name:** [new_name]
**MAC:** [mac]
**IP:** [ip]

**Proceed?** [Yes/No]
```

### Step 3: Execute

```
unifi_rename_client(mac=[mac], name=[new_name])
```

### Step 4: Report

```markdown
## Device Renamed ✓

**MAC:** [mac]
**New Name:** [new_name]

The device will now appear as "[new_name]" in the UniFi UI
and in all reports.
```
```
