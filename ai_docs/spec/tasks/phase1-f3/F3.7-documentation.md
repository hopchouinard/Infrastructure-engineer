## Slash Commands

For common operations, use slash commands for faster, more predictable workflows.

### /infra-find

Find a device and show its connection details.

```
/infra-find "Living Room TV"
/infra-find "aa:bb:cc:dd:ee:ff"
/infra-find "192.168.1.50"
```

**Output:**
```
Device: Living Room TV
MAC: aa:bb:cc:dd:ee:01
IP: 192.168.1.101
Connection: Wired
Switch: Office Switch (port 5)
Network: Default
Last Seen: 2 minutes ago
```

### /infra-isolate

Isolate a device to its own VLAN with optional allowed connections.

```
/infra-isolate "TV"                              # Basic isolation
/infra-isolate "TV" --vlan-name "Media"          # Custom VLAN name
/infra-isolate "TV" --allow "NAS"                # Allow access to NAS
/infra-isolate "TV" --vlan-id 100 --allow "NAS,Plex"
```

**Options:**
| Option | Description |
|--------|-------------|
| `--vlan-name` | Custom name for the isolation VLAN |
| `--vlan-id` | Specific VLAN ID (1-4094) |
| `--allow` | Comma-separated list of devices to allow access to |

### /infra-block

Block a device from the network.

```
/infra-block "Guest iPhone"
/infra-block "aa:bb:cc:dd:ee:02"
```

The device will be blocked at the controller level and disconnected immediately.

### /infra-unblock

Unblock a previously blocked device.

```
/infra-unblock "Guest iPhone"
```

### /infra-guest

Create a temporary guest network.

```
/infra-guest "Party WiFi"                    # Default settings
/infra-guest "Party WiFi" --hours 24         # 24-hour expiry
/infra-guest "Party WiFi" --password "custom123"
```

**Options:**
| Option | Description |
|--------|-------------|
| `--hours` | Hours until network expires (default: 48) |
| `--password` | Custom WiFi password (default: auto-generated) |
| `--vlan-id` | Specific VLAN ID for guest network |

### /infra-audit

Run a security audit on your network.

```
/infra-audit                          # Full audit
/infra-audit --section clients        # Audit clients only
/infra-audit --section firewall       # Audit firewall rules only
```

### /infra-status

Show network status overview.

```
/infra-status                         # Full status
/infra-status --section networks      # VLANs only
/infra-status --section changes       # Recent changes only
```

### /infra-undo

View and undo recent changes.

```
/infra-undo --list                    # Show recent changes
/infra-undo --id 3                    # Undo change #3
```

### /infra-unknown

List devices without names.

```
/infra-unknown
```

### /infra-rename

Rename a device for easier identification.

```
/infra-rename "aa:bb:cc:dd:ee:ff" "Smart Thermostat"
```

## Understanding Change Plans

Before making any configuration changes, Claude will show you a **change plan**
and ask for confirmation.

### Example Change Plan

```
## Proposed Changes

1. Create VLAN
   - Name: TV_Isolated
   - VLAN ID: 100
   - Subnet: 192.168.100.0/24

2. Assign Device
   - Device: Living Room TV (aa:bb:cc:dd:ee:01)
   - From: Default
   - To: TV_Isolated

3. Create Firewall Rule
   - Name: tv_isolated-to-nas-allow
   - Source: TV_Isolated (192.168.100.0/24)
   - Destination: 192.168.1.50 (Synology NAS)
   - Action: Allow

Proceed with these changes? [Yes/No]
```

### Confirming Changes

- Type `yes`, `y`, or `confirm` to proceed
- Type `no`, `n`, or `cancel` to abort
- Ask questions or request modifications before confirming

---

## Undoing Changes

All configuration changes are logged and can be undone.

### View Change History

```
/infra-undo --list
```

Output:
```
Recent Changes:
1. [10 min ago] Created VLAN "TV_Isolated"
2. [10 min ago] Assigned Living Room TV to TV_Isolated
3. [10 min ago] Created firewall rule tv_isolated-to-nas-allow
4. [2 hours ago] Blocked client Guest iPhone
```

### Undo a Specific Change

```
/infra-undo --id 1
```

Claude will show you what will be undone and ask for confirmation.

### Limitations

- Some changes cannot be automatically undone (e.g., client statistics)
- Undoing a VLAN deletion won't restore client assignments
- Very old changes may not have enough context to undo

## Safety Features

The Infrastructure Engineer includes multiple safety mechanisms:

### Protected Networks

You cannot delete these networks:
- Default
- LAN
- Management

### Blocked Operations

These operations are automatically blocked:
- Any-to-any allow firewall rules
- Disabling gateway interfaces
- Deleting protected networks

### Required Confirmations

These operations always require confirmation:
- Creating VLANs
- Modifying firewall rules
- Blocking/unblocking devices
- Bulk operations

### Audit Trail

All changes are logged to `.claude/logs/infrastructure-changes.json` (or path set via `CLAUDE_CHANGE_LOG` env var) with:
- Timestamp
- Operation type
- Parameters
- Result

## Best Practices

### Naming Conventions

- Name all devices for easy identification
- Use descriptive VLAN names (e.g., "IoT_Devices" not "VLAN10")
- Include purpose in firewall rule names

### Before Major Changes

1. Run `/infra-status` to understand current state
2. Run `/infra-audit` to check for issues
3. Have a rollback plan
4. Test in non-production hours if possible

### Regular Maintenance

- Review unknown devices weekly: `/infra-unknown`
- Run security audits monthly: `/infra-audit`
- Clean up temporary guest networks: `/infra-undo --list`

---

## Troubleshooting

### "Cannot connect to UniFi controller"

1. Verify unifi-mcp server is running
2. Check controller URL in configuration
3. Verify API credentials

### "Device not found"

1. Check device name spelling
2. Try searching by MAC or IP
3. Verify device is connected to network
4. Use `/infra-find` with partial name

### "Operation blocked by safety check"

This means a hook prevented a dangerous operation. If you need to proceed:
1. Review the safety concern
2. Consider if there's a safer alternative
3. Contact administrator if override needed

### Changes not appearing

1. UniFi controller may take time to apply changes
2. Check `/infra-status --section changes` for confirmation
3. Verify MCP server received the request

## /infra-isolate

Isolate a device to its own VLAN.

### Syntax
```
/infra-isolate <device> [--vlan-name <name>] [--vlan-id <id>] [--allow <devices>]
```

### Arguments

| Argument | Required | Description |
|----------|----------|-------------|
| device | Yes | Device name, MAC, or IP to isolate |
| --vlan-name | No | Name for the isolation VLAN (default: auto) |
| --vlan-id | No | VLAN ID 2-4094 (default: auto-assigned) |
| --allow | No | Comma-separated devices to allow access to |

### Examples
```
/infra-isolate "TV"
/infra-isolate "TV" --vlan-name "Media Devices"
/infra-isolate "TV" --vlan-id 100
/infra-isolate "TV" --allow "NAS"
/infra-isolate "TV" --vlan-name "Media" --allow "NAS,Plex Server"
```

### Workflow

1. Finds the specified device
2. Surveys available networks for VLAN ID assignment
3. Creates isolation VLAN
4. Assigns device to new VLAN
5. Creates firewall rules for allowed devices (if specified)
6. Reports all changes

### Output
```
✓ Created VLAN "TV_Isolated" (192.168.100.0/24)
✓ Moved Living Room TV to TV_Isolated
✓ Created firewall rule: TV_Isolated → Synology NAS (allow)

Device is now isolated. Use /infra-undo to reverse.
```

```bash

```

## Purpose
Explain what this skill does.

## Workflow

Describe expected output format.

### 3. Skill Activation

Skills activate automatically when Claude determines the user's request
matches the skill's description. Make descriptions specific:

**Good:**
```yaml
description: Handles requests to create temporary guest WiFi networks with time-limited access
```

**Bad:**
```yaml
description: Network stuff
```

## Adding a New Command

### 1. Create Command File

Create `.claude/commands/my-command.md`:

```markdown
---
description: Brief description for autocomplete
allowed-tools: mcp__unifi__*, Read, Grep
argument-hint: <required-arg> [optional-arg]
---

# /my-command

## Arguments
- `required-arg`: What this is
- `optional-arg`: Optional setting

## Workflow
1. Parse arguments
2. Do the thing
3. Report results

## Example Usage
```
/my-command "value" --option
```
```

### 2. Command Naming

- Use lowercase with hyphens: `my-command`
- Prefix with domain: `infra-`, `net-`, etc.
- Keep names short but descriptive

## Adding a New Hook

### 1. Create Hook Script

Create `.claude/hooks/my-hook.sh`:

```bash
#!/bin/bash
# Hook: my-hook
# Trigger: PostToolUse on specific tools
# Purpose: What this hook does

# Read tool call data from stdin
INPUT=$(cat)

# Parse with jq
TOOL_NAME=$(echo "$INPUT" | jq -r '.tool_name')
TOOL_INPUT=$(echo "$INPUT" | jq -r '.tool_input')

# Your logic here
if [[ "$SOME_CONDITION" == "true" ]]; then
    echo "Blocked: reason" >&2
    exit 1  # Block operation
fi

exit 0  # Allow operation
```

### 2. Make Executable

```bash
chmod +x .claude/hooks/my-hook.sh
```

### 3. Register in settings.json

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "mcp__unifi__unifi_*",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/my-hook.sh"
          }
        ]
      }
    ]
  }
}
```

### Hook Types

| Type | Trigger | Can Block |
|------|---------|-----------|
| PreToolUse | Before tool execution | Yes |
| PostToolUse | After tool execution | No |

### Hook Input Format

Hooks receive JSON on stdin:

```json
{
  "tool_name": "mcp__unifi__unifi_create_vlan",
  "tool_input": {
    "name": "Test VLAN",
    "vlan_id": 100
  }
}
```

For PostToolUse, includes result:

```json
{
  "tool_name": "mcp__unifi__unifi_create_vlan",
  "tool_input": { ... },
  "result": { ... }
}
```

### Skills

- Document all available tools
- Include example outputs
